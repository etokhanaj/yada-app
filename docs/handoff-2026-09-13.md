## 2. The project in one paragraph

Yada is a Bible reader. Users read BSB/WEB/KJV, tap a verse, and see the original Greek/Hebrew, what it meant, context, competing interpretations, and connections — then return to reading. All explanation is AI-generated **at authoring time**, human-reviewed, and shipped as static per-book SQLite bundles. No runtime AI, no backend, no accounts in v1. Governing docs (frozen) in `~/Downloads/Yada/`: `bible-untranslated-prd.md` (PRD v6), `yada-build-plan.md`, `yada-design-brief.md`, and numbered prompts `yada-prompt-01…05`. ## Appendix A — agent specs, in case either must be re-run

**Review tool (`packages/review`).** Local-only Node HTTP server on `node:sqlite` (127.0.0.1; DB from `YADA_STAGING_DB` or `<repo>/content/staging.db`) plus a Vite/React client; scripts dev/build/start/test/typecheck/export. Queues: Flagged; a stable, seeded 5–10% sample per book; Adversary disagreements (critical first); Targeted expert (debated claim, model_knowledge grounding, translation_note, quotation/allusion/fulfillment relationship, critical adversary flag — show the reason). The entry view mirrors the app: BSB/WEB/KJV text, whats_happening, "What we can see" (text + context) and "Where interpretation differs" (interpretation + debated) by display_rank with the 3/2 first-screen cap marked; labels, grounding, evidence and positions; gloss table; close_rendering; related passages; flags; `validateVerseEntry` output; adversary flags inline. Actions: approve → `human_reviewed`, requires a rating and is **refused below 4** (0C); reject keeps `flagged` with a required reason (additive `decision` column); j/k/a/r keys; every decision appended to `review/decisions.jsonl`, and `export` regenerates `review/review_state.jsonl`. Design tokens from the brief, Literata / Gentium Plus / Noto Serif Hebrew, no cards or coloured pills, `direction: ltr` on prose containing original-language words. Never write decisions to the real staging.db; tests use temp DBs seeded from `golden/`.

**Pipeline stages.** Shared contract table, used by both components: `adversary_flags(verse_id, claim_id, verdict ∈ upheld|unsupported|miscategorised|compound|overclaimed, severity ∈ critical|minor|none, note, model, created_at, PRIMARY KEY (verse_id, claim_id, model))`.
- `ingest-responses`: parse `content/responses/*.json` with the inspect.ts helpers; store valid entries via `storeVerseEntry(..., "flagged")` and pericope entries; reject review-status claims and `max_tokens` truncations; non-zero exit on any reject.
- `validate <BOOK>`: `validateVerseEntry` plus source-data checks — cited lemmas/Strong's exist in the verse's tokens (0C: 100%), verse and related refs resolve, the gloss matches the derived tokens; per-rule table; non-zero on errors.
- `adversary <BOOK>`: prompt `prompts/adversary.v1.md`, default `claude-sonnet-5`, the same budget gate; writes `adversary_flags`; a non-upheld verdict keeps the entry `flagged`; reports disagreement against 0C (≤10%, 0 critical).
- `regress [--live]`: CI tier with zero API calls (golden Zod + rules + provenance + oracle when raw sources exist); live tier gated, judging structural equivalence against `golden/1co.14.34.json`.
- `publish [--dry-run|--confirm]`: R2 via `@aws-sdk/client-s3`, bundles first and manifest last, sha256 verified, any `unreviewed-dev` bundle refused, credentials from `R2_*` env.
- `.github/workflows/ci.yml` (Node 24, pnpm with frozen lockfile, typecheck, test, regress) and README command lines.
- Every gated stage tested with fake clients: nothing sent without `--confirm`, refusal without a key, the ceiling respected.
