# Milestone 0: go/no-go

Analysis of the first paid generation, 2026-10-09. Three pericopes (GEN.1.1-1.5,
PSA.23.0-23.6, 1CO.14.26-14.40) were each generated by Opus 5 and Sonnet 5
under prompt `pericope@1.1.0`, giving 60 entries. Costs are in
`docs/cost-model.md`.

**Nothing here is reviewed.** Every generated entry is `review.status: flagged`.
The build plan requires a human review pass on this output. That review is
John's to do and has not happened. No sign-off is recorded here.

## Recommendation

**Go for Milestone 1 on Opus 5, one book in batch mode, after prompt 1.2. No-go
for the whole Bible at the current prompt.**

- **Content: go, subject to John's review.** Under prompt 1.1 all 60 entries
  passed the schema. No Strong's number anywhere fell outside the supplied data.
  Across 318 claims and 223 key words I found one wrong parse (Sonnet) and one
  gender overreach (Opus). The failures that remain are discipline failures a
  prompt can address, listed below. None is fabrication.
- **Cost: one pass fits, the PRD budget does not.** A whole-Bible Opus pass is
  £1,388 at the measured 4,259 output tokens per verse (batch discount assumed),
  and £1,856 with the old adversarial allowance. That leaves an 8% margin under
  £2,000. PRD §11.10 also asks the ceiling to hold a full regeneration reserve.
  On that basis the measured cost is about £3,700 on Opus and £2,500 on Sonnet,
  and neither fits. Output per verse has to fall, or the ceiling or the reserve
  has to change. That decision is John's.
- **Model: Opus.** Sonnet is 1.46× cheaper, not the assumed 2.5×, because it
  spends 52% of its output on thinking. Opus's entries are much easier to check.
  93% of its `text` claims cite lexical evidence, and every Opus note is filled
  in, usually with the morphology code. Sonnet cites lexical evidence on 44%
  (none of its 41 in 1 Corinthians), and two-thirds of its notes are empty. Human
  review is the real budget, and that traceability is what makes review fast.
  See "Opus vs Sonnet".

### Strong's numbers and parses not in the supplied data

Checked mechanically against `staging.db`, across all 60 entries rather than
only the three verses:

- **Strong's numbers: 0 violations in either model.** All 185 Opus and 73
  Sonnet lexical citations (claims and positions), and all 116 + 107 key words,
  use a number present
  in the request's chapter tokens. Every key word's number is in its own verse.
  Opus cited H7725 in the Psalm 23:6 debate, and it is in the supplied data
  (verse 3), which the evidence note says.
- **Parses: one error and one overreach.** I checked 114 parse-asserting `text`
  claims against the morphology codes.
  - **Sonnet, wrong:** `psa.23.2-c3` says "מֵי מְנֻחוֹת literally reads 'waters of
    restfulness,' using the plural construct noun מְנֻחוֹת". The supplied tag is
    `HNcbpa`, which is **absolute**. The construct is מֵי (`HNcmpc`). The key-word
    note repeats the error ("Plural construct with 'waters.'"). Sonnet's
    lexical evidence note is empty, so nothing in the entry shows the code that
    contradicts it.
  - **Opus, overreach:** `gen.1.2-c2` says "הָיְתָה is tagged as a Qal perfect,
    third person feminine singular, agreeing with the feminine noun אֶרֶץ". The
    verb parse is exact (`HVqp3fs`), but אֶרֶץ is tagged `Ncbsa`, gender **b**
    (both), not feminine. Agreement licenses "construed as feminine here", but
    the claim states a noun gender the data does not give.
  - Both models reported the supplied tags faithfully where a reader might have
    "corrected" them from memory. For example, both models parse יִרְדְּפוּנִי
    as Piel because the data says `HVpi3mp`.
- **Fixture:** `1co.14.34-c1` cites the note "V-PAM-3P", a Robinson-style code.
  The supplied MorphGNT code is `V- 3PAD-P--`. The parse is right, but the
  evidence string is not in the data. `psa.23.1-c4` cites H4210 as evidence on
  PSA.23.1. Since schema 1.2.0 that token lives in PSA.23.0, so the fixture is
  stale. Both models handle verse 0 as its own entry.

### GEN.1.1

| Check | Fixture | Opus | Sonnet |
|---|---|---|---|
| Atomicity | clean | `c5` bundles: "carries a plain vocal shewa rather than the vowel that would signal an assimilated definite article, so the noun is written without the article" | `c4` bundles: "marks each as a definite direct object and is not itself translated" |
| Text vs interpretation | clean | clean. The disjunctive accent (`c7`) is read correctly off the supplied surface, ṭipḥa | clean |
| `analysis_tradition` | all set | all set ("Masoretic (Tiberian) vocalisation and morphological analysis") | all set, but only "Masoretic" |
| Central dispute | debated, 2 positions | debated, 3 positions | debated, 2 positions, **at pericope level only** (`gen.1.1-5-c4`) |
| Application as context | none | none | none |

- **The absolute/construct dispute.** The fixture has two positions. Its
  "Absolute" case merges two distinct readings: verse 1 as the first act, and
  verse 1 as a heading over the account. Opus's `gen.1.1-c8` separates them
  ("Independent clause reporting the first act" / "Independent clause
  functioning as a summary heading" / "Temporal clause leading into verse 2 or
  verse 3"). It names the temporal reading's proponents ("Rashi and Ibn Ezra,
  followed by the New Jewish Publication Society version") and its grammatical
  arguments, including the missing article and the usual construct use of
  רֵאשִׁית. Its translation note says "the Masoretic pointing is itself part of
  the evidence on both sides". **Opus is right over the fixture**: there are
  three live positions, not two. Sonnet's version tilts. The absolute side gets
  the supplied parse plus "most traditional Jewish and Christian translations",
  while the temporal side gets "translations such as the NJPS Tanakh" and an
  evidence note conceding it is "not drawn from the supplied morphology alone".
  The parse is the Masoretic tradition's reading. Presenting it as the data
  favouring one side is the case `pointed-hebrew-attribution` exists for, one
  level up.
- **בָּרָא with God as subject.** The fixture states it unattributed in a
  key-word note ("used in the Hebrew Bible with God as its subject and never
  takes a stated material"). Sonnet puts it in a debated position dressed as
  lexical evidence ("verb exclusive to divine subjects"). Opus `c6` restricts it
  to the Qal, marks it `model_knowledge`, and adds "Distribution across the canon
  is not recoverable from the supplied verse data alone." **Opus is right**: the
  Piel forms of ברא (Josh 17:15, 18) have human subjects, so the unqualified
  statement is too broad, and none of it is in the supplied data.
- **Who parses.** The fixture's `c5` says "The Masoretic pointing ... parses
  רֵאשִׁית here as an absolute noun". Pointing does not parse. The absolute tag
  is OSHB's analysis of the pointing. Opus's "In the supplied morphology
  בְּרֵאשִׁית is parsed as ..." is the accurate attribution.
- **Smuggled winners elsewhere in Genesis.** In Opus's pericope context claim
  `p5`, ancient Near Eastern accounts "also begin from a watery, undifferentiated
  state rather than from nothing". The "also" presupposes one side of Opus's own
  debated `p6` (creation out of nothing or not). In Sonnet's debated `c5` on the
  plural אֱלֹהִים, one position is "Hebrew grammar generally treats" and the other
  is "Some later Christian readings". That frames grammar against theology, not
  two readings, and the ordering implies a verdict. The fixture's `c10` (plural of
  majesty against inherited divine title) is the better-framed dispute.

| Check | Fixture | Opus | Sonnet |
|---|---|---|---|

- **Placement or authenticity.** The fixture's `c9` frames the dispute as
  "Where verses 34 and 35 stood", with positions "Here, after verse 33" and
  "After verse 40". That omits the interpolation thesis, which is what the
  dispute is actually about. Opus (`c6`: "Original and in place" / "Displaced or
  interpolated"; pericope `c7` adds "Post-Pauline interpolation") and Sonnet
  (`c10`: "Evidence for interpolation" / "Evidence of relocation only") both
  include it. **Both models are right over the fixture.** Opus names the Western
  witnesses (D F G 88* Old Latin Ambrosiaster) and marks them "reported from
  general knowledge; no apparatus supplied", which is honest and inspectable.
- **The fixture tilts.** Its key-word note on σιγάτωσαν says the verb was used in
  verses 28 and 30 "as a situational instruction rather than a permanent ban".
  Applied to verse 34, that settles the scope dispute by analogy. Its
  `whats_happening` ("This verse applies that same instruction to a third
  group") assumes the verses are in place. Sonnet's pericope `c7` turns the same
  observation into a debated claim ("whether it carries the same scope of silence
  in each case"), and that is the right handling.
- **Opus's scope positions overlap.** In `1co.14.34-c7` and pericope `c8`, the
  first position is "Speech in the assembly generally, or authoritative speech in
  particular", tagged with "present-day complementarian interpreters". The second
  is "a defined activity such as weighing prophecies". The weighing-of-prophecy
  reading is itself a leading complementarian reading, so the labels misplace
  the people they name, and two positions are folded into one. This needs fixing
  in review.
- **Women or wives.** The fixture (`c7`) and Sonnet (`c9`) have it as a debated
  claim. Opus records the ambiguity only in a key-word note ("The same noun
  covers both senses; v. 35 mentions husbands") and in a `text` claim on verse 35
  (`1co.14.35-c2`). **The fixture and Sonnet are right; Opus missed a live
  dispute.**
- **Opus used the supplied text.** It noticed that SBLGNT prints 14:32–33a in
  parentheses (`1co.14.32-c3`, true of the supplied tokens "(καὶ" and
  "εἰρήνης)"). It also used 1 Cor 14:21, inside the supplied chapter, as evidence
  that Paul calls Isaiah "the law". Sonnet also debates where 33b belongs
  (`1co.14.33-c2`), but it uses neither piece of supplied evidence. One
  slip: its 33b debate cites the closing parenthesis for the reading that the
  clause "concludes the statement about God". The parenthesis encloses that
  statement, so a clause after it cannot conclude it. The evidence fits
  attaching 33b to verse 31 instead.

What the extra £437 buys, in specific terms:

1. **Checkable evidence.** An Opus parse claim carries the morphology code it
   rests on (for example "Morph code R/Ncfsa, where the final 'a' marks the
   absolute state"). A reviewer can confirm it without opening the
   interlinear. Sonnet cites the verse, or a lexical item with an empty note.
   Its one wrong parse is exactly the kind of error an empty note hides.
2. **Better debates.** Opus gives three positions where the field has three (Gen
   1:1), names proponents, and uses the supplied data on both sides. That
   includes H7725 from verse 3 for the "return" reading of Ps 23:6, the
   parentheses of SBLGNT, and 1 Cor 14:21.
3. **Better attribution of model knowledge.** Opus marks distribution claims as
   `model_knowledge` and says why (Gen 1:1 `c6`). Sonnet presents the same
   knowledge as lexical evidence.

What it does not buy: Opus is more verbose, with more claims per verse, and some
of them carry lexical semantics as `text`. Its evidence-rule violations are 4.7×
Sonnet's. It missed one dispute Sonnet caught. Its translation note on Ps 23:6
("a phrase about extended time rather than endlessness") settles a question its
own claim `c8` leaves open.

## What the prompt still gets wrong, and whether a prompt can fix it

| Problem | Example | Fix | Prompt-fixable? |
|---|---|---|---|
| Debated claims cite evidence only in positions | 17 of 17 rule violations | Add "a debated claim cites at least the verse at claim level, as well as in each position" | Yes |
| Lexical meaning labelled `text` / `source_data` | Opus `psa.23.4-c3`: "שֵׁבֶט denotes a rod or club and is the same noun used elsewhere for a ruler's sceptre and for a tribe." | Send the gloss from the `lexemes` table with each token (`surface\|morph\|strongs\|gloss`), and state that meanings beyond it are `model_knowledge` | Yes, with a pipeline change |
| Fact and inference in one sentence | "..., so the verse does not itself specify what kind of speech is in view" | Add a worked bad/good example, and extend the atomicity heuristic to flag ", so " and "meaning '" in `text` claims | Mostly. The rule change catches what the prompt misses |
| Parse + gloss + meaning bundled (Sonnet) | "...form of חסר ('to lack'), negated by לֹא, meaning 'I shall not lack.'" | Same as above | Yes |
| Evidence notes omit the morph code | 36 of Sonnet's 55 notes empty | Require the supplied morph code verbatim in every lexical note, then add a deterministic rule that checks it against `staging.db` | Yes. The rule would have caught both parse errors |
| Invented `dataset` strings | Opus "strongs", "OSHB morphology (BHS)"; Sonnet "OSHB" | Stamp `dataset` in `assemble.ts` like ids and versions, and remove it from `GENERATION_SCHEMA` | Yes, pipeline only |
| Winners smuggled outside claims | Opus Ps 23:6 translation note; Sonnet "Paul instructs" | Add "whats_happening and translation_note must not settle anything a debated claim leaves open" | Partly. Detecting it needs the adversary or a human; this is the residual model limitation |
| Winner smuggled inside a position | Sonnet "more plausibly concerns" | Forbid comparatives ("more plausibly", "most", "generally") in position cases | Partly |
| Output volume | 4,259–4,902 tokens per verse | Cap claims per verse entry, shorten the pericope entry, ask for compact JSON with no fence | Yes. This is the main cost lever |

Nothing in the sample looks like a model limitation that a prompt cannot reach,
except smuggling in free prose. That needs the adversarial pass and review, which
the design already assumes.

## Fix before scaling

1. **Prompt 1.2** with the fixes above, re-run on these three pericopes, and
   `inspect` again. These entries become the regression baseline.
2. **A parse-consistency rule:** a lexical evidence note must quote the supplied
   code, and the code must match `staging.db` for that Strong's number in the
   cited verse. It is cheap and deterministic, and it would have caught both
   parse errors here.
3. **Account for the two timed-out Opus attempts.** They are missing from
   `usage.jsonl`. Worst-case logging now exists (`ed2db74`), but this session's
   ledger is incomplete by $0 to $4.36. Reconcile it against the console invoice.
4. **Exercise the Batches API** before relying on its 50% discount. Every
   projection assumes it.
5. **Pericope length versus the 128k cap.** At Sonnet's rate a pericope of about
   33 verses hits it. Split long pericopes, or measure first.
6. **Set an output target** that fits whatever budget John settles on. On Opus,
   about 2,170 tokens per verse fits generation, adversary and one full
   regeneration in £2,000. The measured figure is 4,259.
7. **Log elapsed time** in `usage.jsonl`. Without it, the timeout cost and batch
   latency cannot be estimated.
